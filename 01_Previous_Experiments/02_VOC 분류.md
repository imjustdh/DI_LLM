
# 02. VOC 분석 자동화 실험

## 1. 추진 배경

기존 VOC 분석 업무는 수집된 데이터를 대상으로
수동 전수조사와 엑셀 기반 분석을 수행하는 방식이었음.

대용량 데이터를 분석하는 과정에서 많은 시간이
소요되었으며, 반복적인 검수와 원문 확인에 따른
업무 부담이 존재함.

이에 LLM을 활용하여 기존 분석 과정의 처리 속도와
사용성을 개선할 수 있는지 확인하고자
VOC 분석 자동화 기능 구현을 시도함.

본 작업은 정식 프로젝트 추진 이전에
개인 샌드박스 환경에서 진행한 사전 실험임.

---

## 2. 1차: VOC 분석 기능 구현

### 2.1 개발 방향

기존 엑셀 데이터를 활용하면서 반복적인 분석 과정을
자동화할 수 있도록 Jupyter Notebook 환경에서
기능을 구현함.

전체 분석 과정을 한꺼번에 자동화하기보다는
업무에 필요한 기능을 구분하여 구현함.

주요 구현 기능은 다음과 같음.

- 페이드(광고·협찬성 게시물) 탐지
- 질문 기반 원문 VOC 추출
- 소비자 반응 분류 및 이슈 요약
- 분석 진행 상황 확인 및 오류 복구

### 2.2 데이터 처리

짐빔 관련 VOC 데이터를 대상으로 기능을 구성함.

기존에 수집된 엑셀 파일의 문서번호, 제목,
내용, 수집 기간, 채널 및 URL 정보를 활용함.

파일의 열 위치가 달라지더라도 적용할 수 있도록
열 이름을 기준으로 데이터를 읽는 방식을 사용함.

또한 원본 엑셀을 직접 수정하지 않고,
분석 결과를 별도로 저장하도록 구성함.

### 2.3 페이드 탐지

광고 및 협찬성 게시물을 선별하기 위해
규칙 기반 탐지와 AI 판정을 결합함.

1. 광고·협찬 관련 표현을 기준으로 후보 탐지
2. 탐지 규칙에 따라 확실·예비 후보 구분
3. 추가 확인이 필요한 후보에 AI 판정 적용
4. 근거 문장 및 판정 이유 표시
5. 담당자가 최종 검수할 수 있도록 구성

규칙에 해당하지 않는 게시물과 AI가 확인한
게시물을 구분하고, 사람의 최종 검수 결과를
반영할 수 있도록 구현함.

### 2.4 질문 기반 VOC 추출

기존의 키워드 중심 검색에서 나아가,
사용자가 입력한 질문에 직접 답하는
원문을 추출하는 기능을 구현함.

예를 들어 특정 제품에 관한 소비자 반응을
질문으로 입력하면, 해당 질문과 관련된
실제 경험·선택·평가가 포함된 원문을 추출하는 방식임.

단순히 질문의 키워드가 등장하는 게시물이 아니라
질문에 직접적인 근거를 제공하는 문장을
구분하도록 설계함.

추출 결과에는 원문 근거와 함께
질문에 대한 답변 및 맥락 설명을 포함하도록 구현함.

### 2.5 소비자 반응 분류 및 요약

추출한 VOC를 바탕으로 소비자 반응을
분류하고 주요 이슈를 요약하는 기능을 추가함.

- 긍정·부정·중립 및 불명확 반응 구분
- 반응 내용에 따른 카테고리 분류
- 유사한 반응의 이슈별 요약
- 원문 근거와 AI 해석 구분
- 요약 결과와 관련된 원문 확인

하나의 VOC에 상반된 반응이 존재할 수 있다는 점을
고려하여 이슈별로 감성을 구분하도록 구성함.

### 2.6 안정성 및 작업 관리

대용량 데이터를 처리하는 과정에서
작업이 중단되더라도 처음부터 다시 실행하지
않도록 중간 결과 저장 기능을 구현함.

- 처리 진행률 표시
- 완료 데이터 저장
- 작업 일시정지 및 재개
- API 오류 발생 시 자동 재시도
- 실패 문서 별도 관리
- 중복 API 요청을 줄이기 위한 결과 캐시

### 2.7 구현 및 검증 결과

페이드 탐지, 질문 기반 VOC 추출,
소비자 반응 분류 및 요약 기능을
하나의 노트북에서 실행하도록 구성함.

노트북 기록에는 모의 API를 이용한
오류 재시도, 체크포인트 복구,
일시정지 및 원문 검증 등 주요 기능의
테스트 과정이 정리되어 있음.

다만 해당 검증만으로 실제 외부 API를 이용한
전체 데이터의 분류 정확도나 처리 성능이
입증된 것은 아님.

## 3. 2차: Streamlit 웹 애플리케이션 구현

### 3.1 확장 배경

1차에서는 Jupyter Notebook 기반으로
분석 기능을 구현함.

이후 기존 분석 기능을 웹브라우저에서
이용할 수 있도록 Streamlit을 활용한
웹 애플리케이션 형태로 확장함.

### 3.2 주요 개선 내용

**① 웹 기반 사용자 인터페이스**

노트북에서 설정하던 주요 분석 조건을
웹 화면에서 입력하고 실행할 수 있도록 구성함.

엑셀 업로드, 분석 조건 설정, 기능 실행,
진행 상황 확인 및 결과 확인 기능을 구현함.

**② 작업 저장 및 공유**

분석 작업별로 작업 코드를 생성하고,
해당 코드를 통해 저장된 작업을 다시
불러올 수 있도록 구성함.

작업별 데이터와 분석 결과를 분리하여
저장하도록 구현함.

**③ 장시간 분석 작업 관리**

브라우저 사용과 분석 작업을 분리하여
서버에서 분석을 처리하도록 구성함.

작업 진행률, API 호출 횟수,
캐시 사용 및 오류 발생 현황을
웹 화면에서 확인할 수 있도록 구현함.

**④ 분석 결과 확인**

페이드 탐지 결과를 검수하고,
질문 기반 VOC 추출 및 소비자 반응
요약 결과를 화면에서 확인하도록 구성함.

주요 결과는 CSV 형태로 다운로드할 수 있음.

### 3.3 서버 운영을 고려한 구성

분석 데이터 및 작업 상태를 서버에 저장하고,
작업 중단 시 저장된 결과를 활용하여
재개할 수 있도록 구현함.

환경변수를 이용한 API 키 설정,
공유 접속 암호 및 서버 실행 설정을 포함함.

다만 실제 서버 배포 및 다중 사용자 환경의
운영 안정성은 별도 검증이 필요함.

## 4. 구현 과정에서의 주요 변화

| 구분 | 1차 | 2차 |
|---|---|---|
| 사용 환경 | Jupyter Notebook | Streamlit |
| 주요 목적 | 분석 기능 구현 | 웹 기반 사용 환경 구성 |
| 분석 설정 | 코드 및 노트북 UI | 웹 화면 |
| 작업 관리 | 체크포인트 | 서버 작업 관리 |
| 결과 확인 | 노트북 출력 | 웹 화면 및 CSV |
| 작업 공유 | 결과 파일 | 작업 코드 |

1차에서 분석 기능을 구현하고,
2차에서는 해당 기능을 다른 사용자가
웹브라우저에서 이용할 수 있도록 확장함.

- 원문 근거를 유지하는 분류 및 요약 구조

- 분석 기능을 웹 애플리케이션으로
  확장하기 위한 기본 구성
